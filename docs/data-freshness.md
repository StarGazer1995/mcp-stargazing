# 数据时间身份与新鲜度边界

获取时间、预报有效时刻、模型起报时间、数据集版本和计算缓存寿命表达不同的事实。
一次请求刚刚返回，不能证明来源刚刚更新；`resource_id` 相同也不能证明结果仍是同一版。
没有来源时间/版本证据时保持未知，不用计算时间或默认 TTL 补成“最新”。

| 数据层 | 当前可用的时间身份 | 当前复用/失效边界 | 仍未知或待实现 |
|---|---|---|---|
| 天气 | provider 的小时有效时刻及已有来源信息；当前条件和日值不能代替目标夜间小时 | 多夜规划仅在该次请求内复用原始天气取回结果，每夜重新筛选有效小时；没有 MCP 跨请求天气结果缓存 | 有效时刻不等于起报时刻；缺失起报/更新时间不能靠请求完成时间反推；尚无统一的 provider 陈旧阈值 |
| 大气模型 | 每数据集的 `retrieved_at`、可选 `model_run_time`、覆盖起止与逐字段来源 | 已选窗口只使用同 provider、精确时刻和来源覆盖内的数据；缺失/超范围仍未知 | 数据存在不证明已校准，也不证明模型在所选地点的准确率 |
| 地点计算结果 | 查询 `resource_id`；进程内结果发布 revision 和单调经过时间 | 默认 3600 秒、128 条 LRU；达到 TTL 即失效，读取不续期；进程重启清空；同步分页与后台任务共用此边界 | 显式中央配置路径/元数据变化会失效；上游数据库/GeoTIFF/DB配置/默认文件版本仍未观察；缓存年轻不代表地点资料年轻 |
| 光污染 | bridge 返回的 overlay 名称/模型值等已有字段 | 独立网格请求委托 SPF；地点结果中光污染字段随地点计算缓存复用 | MCP 不提供统一的数据集年代、更新时刻或源版本失效事件；不能把实时请求说成实时光污染测量，上游缓存仍由提供方负责 |
| 内置地名与天文计算缓存 | 随部署代码/数据文件及计算输入确定；部分计算有进程内 LRU | 内置文件与确定性计算复用不等于实时 provider 更新 | 不据缓存命中虚构地址核验日期或观测资料时效 |

主规划 evidence 的 `retrieved_at` 是组装该次规划证据的时刻；不能据此推断缓存地点、
道路、光污染地图或天气模型的实际更新时间。大气来源自带的取回/起报字段保留其独立
含义。没有在现有公共模型中添加猜测性的 `fresh=true`，也不改历史/v1 契约。

## 地点缓存的经过时间规则

`AnalysisCache` 用单调时钟记录发布时刻与后续读取的经过时间，避免 NTP/手工系统时间
校正造成过期结果继续可读，或尚未到期结果被提前逐出。达到 TTL 的条目在读取时删除；
仅改页码不会续期或改变查询标识。重新计算/重新发布会生成新的内部 revision，旧后台
任务不能读到新发布的内容，仍使用既有 `TASK_RESULT_EXPIRED`。

这不改变后台任务自身的 UTC 状态时间、执行期限或元数据保留策略，也没有增加后台
清扫服务。生产缓存另观察显式 `STARGAZING_CONFIG` 的路径及文件元数据，变化时
清除旧结果、换代，并拒绝计算中旧配置的发布。TTL 与配置失效分别生效：命中不续期，
配置变化无需等到 TTL；失效后的新计算从实际发布时开始新 TTL，旧任务不能读取它。

该观察不读取配置内容，也不是内容哈希或资料年龄。数据库/GeoTIFF、DB 连接配置、
隐式默认文件及下层 GIS 缓存版本仍未观察；其变化后现存条目可能保持到 TTL/容量驱逐/
进程结束。后续源版本失效需联动底层连接或 handle 重建，整套新鲜度模型仍未完成。

回归使用可控时钟、真实同步分页/SDK 和后台结果读取构造软件反例；不修改系统时间，
不证明线上可用率、数据实测年龄、预报准确率或性能改善。
